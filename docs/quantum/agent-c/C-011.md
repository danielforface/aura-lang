## Follow-up checkpoint — CLI negative-test early exit reliability

Interim Q28-reference CI demonstrated a race in two old negative
tests that spawn a subprocess with an invalid CLI flag. The child
legitimately exits before consuming stdin; an unconditional
write_all().unwrap() in the test helper intermittently treated this
expected BrokenPipe as a test failure. The existing noisy helper
was repaired in the earlier C-011 code commit, and symbolic
source PR run #42405136236 confirmed the same race independently.
The source-level helpers for symbolic, stabilizer and original
pure CLI have now been given the same narrow correction:
only a non-empty invalid-flag invocation may return BrokenPipe,
while the test still asserts the required exit code, empty stdout
and structured fail-closed stderr. No simulator/CLI production code
or request/result schema changed. This is a CI reproducibility
correction, not a quantum feature or a relaxation of the error gate.

The pre-correction full C-011 Push #42405357319 and PR
#42405361302 each passed all three scoped Q28 jobs and the real
dispatch subprocess oracle (100 positive, 17 negative). Because
this test-only reliability edit changes HEAD, it requires its own
final exact-SHA Push/PR CI before whole-phase handoff.
