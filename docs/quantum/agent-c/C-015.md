# C-015 — High-shot bounded Counts delivery (Agent C)

**Before:** `FactorCircuit::execute_shots` retains a vector of
all per-shot registers and traces and rejects >1,024 shots.
Restarting seeds for chunked batches would also change the quantum
sampling stream.

**After:** `FactorCircuit::execute_counts` has a real shared
per-shot quantum kernel, consumes one continuous SplitMix64 stream,
and aggregates up to 65,536 shots without storing traces/shot records.
A *new* strict counts-only JSON v1 protocol and the offline
`aura-quantum-counts-run` binary expose it independently of the
existing detailed result API. Supports dynamic reset and classical
feedforward, up to 4,096 unique outcomes, 268,435,456 conservative
CPU units and a separate logical per-bin histogram memory charge.
Unwritten classical bits remain `?`; all invalid/unbounded
inputs fail closed, no partial result or QPU spending.

**Changed production:** `aura-quantum-sim/src/factorized.rs`
(typed `FactorCounts`, common seeded `run_one`),
`src/factorized_counts_json.rs`, `src/bin/aura-quantum-counts-run.rs`,
internal `factorized_json::Operation` crate-only reuse,
`src/lib.rs` exports. Detailed CLI schema is UNCHANGED.
**Acceptance:** 10 Rust aggregate-vs-detailed and safety tests,
6 actual offline CLI tests, 65,536-shot running Rust example,
separate 65,536-H / 32,768-Bell JSON fixtures, external Qiskit
independent Born-rule binomial six-sigma check with byte-identical
seed replay; existing five-engine reference, projective dynamic
and exact-control oracles all retained. Correct scientific scope:
CPU f64 tensor-product model, not formal theorem, approximate
