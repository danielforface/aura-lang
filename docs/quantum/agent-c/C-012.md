## BEFORE → AFTER — observable product

BEFORE: Dense pure-Statevector limited to ≤12 total wires;
Clifford tableau handles 128 but rejects T; density handles 6
and symbolic exact ring handles 4. A large circuit of independent
2-wire entangled Bell+T blocks was **unsupported** even though
each isolated factor is cheap.

AFTER: `aura-quantum-sim/src/factorized.rs` implements a true
**tensor product of independently stored complex-f64 factors**:
H/X/Y/Z/S/T on local factor, CNOT/CZ on one factor or
an **atomic** factor join, SWAP cross-factor by *coordinate
relabeling*, exact conditional projective measurement semantics
within the numeric source profile and seeded reset/feedforward.
No SVD and no truncation; width >10 within one entangled
component or over-budget temporary join → fail closed.
Observed 128q demo uses 64 Bell pairs with a T on every
odd wire; just **4,096 current complex-state bytes**
(64 factors × 4 amplitudes × 16 bytes each) vs impossible
global dense allocation. Factor count/connections and any
local selected amplitudes are inspectable.

An additive offline strict `aura.quantum.factorized-request/1`
→ `aura.quantum.factorized-result/1` exposes this production
behavior through `src/factorized_json.rs` and
`src/bin/aura-quantum-factorized-run.rs`.
It supports optional single-shot factor wires, one requested
computational basis probability over 128 wires, or full f64
complex amplitudes for ≤8 wires. Sampled shots carry trace,
seed, histogram, engine version, numeric tolerance, factor
limit, explicit *zero tensor truncation* metadata and
`qpu_hardware_jobs=0`. Error requests produce structured
stderr and exit 2, with no partial stdout. 128 globally
entangled T qubits are NOT supported; this engine does not
claim general-purpose scalable simulation or exact complex
arithmetic.

The existing capability-first unified dispatcher has an
**additive** fifth backend `factor_product` for >12-wire
non-Clifford sampled circuits or explicit factor inspection /
`mode=factorized`. A connected >10-wire factor remains a
hard error and is **never** silently retried using some
alternate simulator. Existing independent four engine schemas
and gates remain untouched.
